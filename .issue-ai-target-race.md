## Evidence

AI feedback loads an eligible active `user_words` target before reserving and persisting the attempt.
If the learner removes that word after the authoritative lookup, `createPending` still inserts a
learner sentence and feedback attempt, and the provider is called against the now-deleted target.

The deterministic red test captures the target row, performs the normal soft delete, and resumes the
submission. On `origin/main` `bfcecef`, it resolves successful feedback and calls the provider rather
than returning `target_not_found`.

## Contract

AI features section 2 requires an eligible target that belongs to the authenticated learner. Section
6 requires authoritative target loading before persistence and provider work. Soft-deleted saved
words are no longer eligible; learner sentences and feedback attempts must not be created for them.

## Plan

- Add forward migration `0010` with a narrow `learner_sentences` insertion guard only when
  `user_word_id` is present. It requires that linked word to remain active and aborts the creation
  batch before a feedback attempt exists.
- Do not constrain review-origin feedback: review attempts remain historical evidence after a word is
  removed, so the guard applies only to word-linked sentence practice.
- Map only the deterministic trigger error to existing `target_not_found`; release the lease and do
  not call the provider or finalize rewards. Update migration inventory/docs and fresh/repeat/failed
  local-D1 fixtures.

## Acceptance

- A soft delete after target lookup returns `target_not_found`, with no sentence, attempt, provider
  call, reward, activity, or usage side effect.
- Valid active word-detail feedback and valid review-attempt feedback remain supported.
