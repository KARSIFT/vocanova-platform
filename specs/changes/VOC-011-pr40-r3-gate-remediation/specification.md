# VOC-011 Specification

## Objective and authority

Founder direction in issue #39 comment `5047420157` authorizes preparation of this
package only. It requires correction without retroactive validation of PR #40 and
grants no candidate approval, merge, deployment, release, or autonomous authority.

## Stable requirements

- **VOC-011-R01:** Adopt and synchronize this complete package before remediation.
- **VOC-011-R02:** Preserve PR #40's exact base, candidate, merge, timestamp, tree,
  checks, zero-comment, zero-review, and missing-canonical-evidence facts.
- **VOC-011-R03:** Never post or reuse the external report retroactively to validate
  PR #40; never treat the invalid merge as valid VOC-010 adoption.
- **VOC-011-R04:** Derive the revert mechanically from the exact PR #40 diff and reverse
  exactly its ten paths without reverting VOC-011 or later valid history.
- **VOC-011-R05:** After the revert, restore the pre-PR-40 absence of VOC-010 files and
  index entry while retaining a complete failure/remediation audit trail.
- **VOC-011-R06:** Prepare fresh VOC-010 adoption only after the revert merges, from
  then-current `develop`, in a separate PR.
- **VOC-011-R07:** The fresh adoption must introduce the complete approved VOC-010
  package/index content atomically and receive a new exact-SHA independent report
  recorded on GitHub before merge.
- **VOC-011-R08:** Historical PR #40 checks or external verification cannot satisfy any
  fresh-candidate gate; content/tree equivalence is evidence only.
- **VOC-011-R09:** Require authorized human merge for every stage and keep automatic/
  autonomous merge disabled.
- **VOC-011-R10:** Separately synchronize VOC-011 completion and fresh VOC-010 adoption
  evidence before any VOC-006 correction begins.
- **VOC-011-R11:** Change no application, dependency, governance-authority, workflow,
  deployment, infrastructure, production, secret, release, or activation-state path.
- **VOC-011-R12:** Use the highest path/semantic risk, fresh verification, deterministic
  checks, exact inventories, and reverse-apply proof for every candidate.
- **VOC-011-R13:** Keep issue #39 open through remediation and the later VOC-010
  correction/final-sync workflow.
- **VOC-011-R14:** Preserve reversibility and immutable Git/GitHub evidence; never
  rewrite history to conceal the failed gate.

## Decisions and effects

- **VOC-011-D01:** Missing canonical pre-merge evidence is a process failure even when
  an external report existed and content checks passed.
- **VOC-011-D02:** Remediation is revert plus fresh adoption, not retroactive evidence.
- **VOC-011-D03:** Routine R3 requires independent verification but no standing founder
  or technical-steward approval merely because it is R3.
- **VOC-011-D04:** No VOC-006 correction authority exists through PR #40.

The package and remediation process no learner data or credentials and change no
runtime behavior, security, privacy, analytics, accessibility, or deployment state.
