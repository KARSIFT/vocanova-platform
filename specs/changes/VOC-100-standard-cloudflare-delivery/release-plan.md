The plan and implementation merges are repository-only. They do not deploy. GitHub
environment/secret setup and a maximum-90-day standing staging delegation require
separate exact action authority. The delegation names dispatcher `m-e-h-r-d-a-a-d`
and a fresh, non-author AI subagent as per-run review decision-maker, plus a named
mechanical approval proxy; every run remains SHA/attempt-bound. For agent-mediated
dispatch the reviewer uses a different model from the coordinator. GitHub records the
proxy as `m-e-h-r-d-a-a-d` and cannot prove receipt authorship. The separate R4 action
record must explicitly accept that residual or staging remains disabled. Production,
paid spend, DNS change, learner data, and launch remain prohibited.

## Rollback

Stop before write on settings, token, account, manifest, resource, cost, migration,
or production drift. On settings failure, remove the incomplete environment/secrets
and restore documented pre-state so PR2 is not needed for a false result. On rotation,
keep the prior token unrevoked until the installed replacement passes the no-write
environment check; otherwise reinstall the prior value and revoke the replacement.
Revoke compromised/over-scoped tokens immediately. On promotion/smoke failure,
restore both exact pre-promotion Worker version IDs. Do not attempt automatic D1 rollback; use the
reviewed forward corrective migration path. Revert repository policy only through a
reviewed rollback PR and keep live settings documentation truthful. On missing,
mismatched, stale, conflicting, altered, or unauthorized receipt/proxy behavior,
cancel before writes; if writes occurred, stop delivery, revoke the token,
disable/remove the environment secrets, rotate/revoke the affected GitHub session as
applicable, audit the run, and require reviewed correction before reactivation. A
valid forged receipt is not claimed detectable; discovery invokes the same response.
