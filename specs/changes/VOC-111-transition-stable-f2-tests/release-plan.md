# VOC-111 — Release Plan

## Repository-only delivery

VOC-111 has no staging or production release. After exact plan review, adoption, and
normal non-author plan merge, a different builder may prepare one implementation PR
changing only the focused test. Implementation merge changes repository history only;
it does not dispatch, deploy, mutate settings/resources/data, or implement VOC-105.

## Preconditions and repository outcome

Before implementation merge, require the exact single-file diff; current and both
synthetic profile positives; profile-selector mutation matrix; profile-independent raw
duplicate negatives; plan-owned pre/future source positives and marker removals; all
ten one-surface hybrid directions; full VOC-110 and VOC-109 evidence; focused,
foundation, workspace, governance, risk, path, whitespace, hosted, and rollback PASS;
exact-SHA specialist and independent cross-model R3 PASS; zero blockers; truthful
merge eligibility; and a separate non-author merge actor.

The repository outcome is a transition-stable test harness. Runtime validator behavior,
profile contracts, milestone truth, package scripts, documents/evidence, and action
authority are unchanged.

## Bounded observation contract

The accountable VOC-111 owner recorded at adoption observes from implementation merge
through the first refreshed real VOC-105 candidate's two runtime validators, focused
suite, `ci:foundation`, and hosted required checks. The signal includes exact live
profile selection and continued pass/fail behavior for both profile fixtures,
duplicates, hybrids, all VOC-110 negatives, and the VOC-109 tail.

Recurrence of any issue #206 failure, runtime/test disagreement, hybrid/false-profile
acceptance, or protected-evidence regression stops VOC-105 merge and VOC-111 closure.
The owner records linked evidence and routes a separately governed correction or
one-file revert. A formally governed VOC-105 abandonment/supersession is the only
alternate bounded end condition. Observation authorizes no external effect.

## Rollback

Before merge, close the PR. After merge but before VOC-105 lands, revert the one test
file through a separately reviewed PR. If VOC-105 has landed, revert it first when
needed to retain a passing dependency-ordered tree, then revert VOC-111. No rollback
step calls Cloudflare, modifies settings/secrets, reverses D1, changes traffic/DNS,
accesses data, spends, or launches.

## Independent verification and closure

Record planner, builder, specialist, verifier, and merge actors; exact SHAs; verdicts
and resolved findings; hosted results; rollback proof; merge/post-merge readback; and
bounded observation. Model provenance is defense in depth, not authority. Issue #206
closes only after exact implementation and observation evidence; VOC-105 retains its
own implementation/review/merge/closure requirements and all inherited holds.
