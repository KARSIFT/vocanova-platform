# VOC-006 Tasks

## VOC-006-T01 — Re-verify authority and base

Confirm adopted VOC-006 authority, open issue #19, live `develop`, applicable
instructions, completed VOC-005 foundation, and absence of conflicting target work.

## VOC-006-T02 — Establish the canonical App Router root

Convert only existing `apps/web` into a genuine Next.js App Router application and
prove no alternate web root exists.

## VOC-006-T03 — Add minimal rendering and styling

Add the minimal layout, technical root page, global styles, and approved Tailwind CSS
foundation without product UI, design-system expansion, or speculative routes.

## VOC-006-T04 — Wire and prove the production build

Replace skeleton build behavior with a real Next.js build reachable through the
approved web/root command model.

## VOC-006-T05 — Prove bounded development startup

Start the real development server, wait for readiness, request the minimal page, and
terminate deliberately with truthful bounded evidence.

## VOC-006-T06 — Wire real type and lint validation

Configure supported Next.js-aware TypeScript and lint paths, propagate failures, and
remove obsolete/no-op behavior.

## VOC-006-T07 — Resolve and lock minimal stable dependencies

Use authoritative upstream sources, exactly pin only required stable packages, record
rationale, update the lockfile, run frozen installation, and inspect supply-chain
changes.

## VOC-006-T08 — Preserve workspace and governance validation

Run existing root, web, API, workspace, foundation, and governance checks; justify
every necessary integration change outside `apps/web`.

## VOC-006-T09 — Inspect scope and safety

Review exact files and full diff for product/auth/API/backend/later-F2 work, direct
data access, deployment/autonomy, secrets, generated clutter, and unrelated changes.

## VOC-006-T10 — Publish and independently verify implementation

Create a separate draft implementation PR, classify its exact diff, record all
evidence, obtain required exact-SHA independent review, and stop without merge,
deployment, self-approval, auto-merge, or issue closure.

## Task traceability

`T02` through `T10` implement acceptance criteria `AC-01` through `AC-12` as mapped
in `acceptance-criteria.md`; `T01` enforces the authority precondition and is evidenced
by `VOC-006-EV-01`.
