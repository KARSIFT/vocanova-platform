# VOC-117 — Release Plan

## Repository delivery only

This R3 correction has no product or environment release. After exact plan review,
adoption, and normal plan merge, one independently reviewed implementation PR targets
`develop` and changes only the focused supervisor test. A merge changes repository
test evidence only; it does not deploy, dispatch, migrate, access Cloudflare, read
secrets or production/learner data, change DNS/traffic, spend, promote `main`, or
launch.

## Preconditions and gates

- Exact issue/run/job/candidate/base linkage and nine-file package validation.
- Exact one-file implementation path and untouched runtime/docs/package/workflow
  preservation proof.
- Focused positive SIGINT/SIGTERM readiness/outcome tests and bounded negatives.
- Exact disposable mutation matrix: marker omission/rename, split output, marker
  order, fixed-delay reintroduction, and expected-code changes.
- Complete `pnpm run ci:foundation`, `pnpm validate`, governance, risk, format, and
  diff checks with hosted required checks on the exact final SHA.
- Distinct local-process lifecycle specialist PASS and independent cross-model R3
  PASS from non-author actors; all blockers resolved; separate non-author merge actor.
- No self-modification, permission, workflow, dependency, credential, external, or
  production authority expansion.

## Activation and monitoring

Activation is only the separately eligible repository merge into `develop`; no live
activation exists. The adoption-recorded owner monitors the exact merge-SHA CI and
required aggregate until completion and records on issue #221:

- exact merge SHA/tree and hosted run/job URLs;
- focused and complete foundation test counts, conclusions, and durations;
- `ci required` result and exact one-file scope readback;
- child readiness, expected 23/24 outcomes, `forced === false`, and settled cleanup;
- any timeout, leaked child/listener/timer, unexpected forced kill, or recurrence.

Closure requires complete pass evidence, no recurrence, no scope/command/discovery
drift, and no unresolved review finding. A failure stops closure and routes a new
governed correction or a complete revert; no automatic retry or test weakening is
allowed.

## Rollback

Rollback triggers include a false readiness acceptance, an unbounded/hanging waiter,
resource leak, marker-order regression, changed signal outcome, changed runtime
semantics, foundation/aggregate failure, scope drift, or documentation contradiction.

Before merge, close/discard the implementation branch for zero effect. After merge,
revert the complete one-file implementation through a normal reviewed PR, restore the
actual first-parent test file, and rerun focused, foundation, governance, risk,
format, and diff checks. Do not partially revert the helper, retain fixed-delay tests
without a governed decision, or remove expected exit-code assertions. Record the
revert and its evidence on issue #221; historical failure evidence remains intact.

## Independent verification, authority, and closure

Plan and implementation reviewers are distinct actors and do not author the exact
revision. Each exact R3 review uses a recorded model distinct from that revision's
builder; cross-model evidence is defense in depth, not authority. `automatic_merge_allowed:
true` remains package policy only and never merges or bypasses CI, evidence, review,
risk, action-specific authority, or EHR. No founder/steward approval is inferred from
R3. There is no external-effect authority or action-specific hold in this repository
test correction.
